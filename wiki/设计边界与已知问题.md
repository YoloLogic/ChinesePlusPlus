## ✅ 有意为之（不是 bug）

| 现象 | 为什么这样设计 |
|:---|:---|
| 诊断前缀 `error:` / `warning:` / `note:` 保持英文 | 便于工具解析、与上游日志格式兼容；**正文**是中文 |
| 来自 MSVC 头文件的 `note:` 是英文 | 那些话是微软头里写死的，不是本项目生成的 |
| 中文关键字**不能当标识符** | 与英文同一规则：`if` 也不能当变量名 |
| 只有关键字/诊断/标准库别名汉化，不改语义 | 英文写法与中文写法编出的目标码一致，这是底线 |
| 目前只做 Windows x64 主线 | Linux 版另有独立仓库维护 |

## 🛠️ 已修复（曾经是坑）

## ⚖️ 与上游的关系

```text
Clang / LLVM                     ← 上游
    │  fork（中文关键字改在词法/语法层）
    ▼
Chinese++  chinese++.exe
    ├── 中文关键字 99 个
    ├── 中文诊断 7300+ 条
    ├── zhstdlib 119 个头
    └── 与 MSVC 二进制兼容（既有库照常链接）
```

- 许可：原创部分**自定义条款**（源码公开 + 禁止重新发布），见 `LICENSE-SCOPE.md`；
- 与 **Standard C++ Foundation / CppCon** 无隶属或背书关系；
- **不使用** C++ 官方徽标的修改版或衍生版；主图标自绘（红底「中」字）。

## 🔍 怎么复核上面每一句话

```powershell
# 1) 包内自检（29 项）
pwsh -File <包根>\verify.ps1

# 2) 中文头不靠 -I
chinese++ -std=c++20 你好.cpp -o 你好.exe; .\你好.exe

# 3) 真实搜索路径（应有 5 条 zhstdlib）
chinese++ -x c++ -E -v -

# 4) 关键字不能当标识符（必须报错）
#    写 整数 大小() { 返回 1; }  →  "（关键字） 大小 不能用作标识符"

# 5) 中英等价（同一逻辑分别用 if/return 与 如果/返回 写，行为应一致）
```

<details>
<summary><b>为什么我把这些写进 wiki 而不是直接改代码</b></summary>

`bundled` 底座属于 C++ 语言线的工作（要给包补齐 SDK 头子集，或把 mingw 头接上，
但 mingw 头 + MSVC ABI 会打架）。打包侧能做的只有：**把模式标成 `system` 并在文档里写清
"必须装 VS Build Tools"** —— 让用户知道边界，而不是假装开箱即用。

</details>
