# 设计边界与已知问题

> 这一页的目的：让"看起来像 bug 的东西"和"真 bug"分开。省得你花时间在**有意为之**的地方。

## 一、有意为之（不是 bug）

| 现象 | 为什么这样设计 |
|---|---|
| 诊断前缀 `error:` / `warning:` / `note:` 保持英文 | 便于工具解析、与上游日志格式兼容。**正文**是中文 |
| 来自 MSVC 头文件的 `note:` 是英文 | 那些话是微软头里写死的，不是本项目生成的 |
| 中文关键字**不能当标识符** | 和英文关键字同一规则：`if` 也不能当变量名 |
| `不属于` MSVC 生态 | 反过来：**与 MSVC 二进制兼容**是硬要求；为了兼容，部分 ABI 细节不能动 |
| 只有关键字/诊断/标准库别名汉化，不改语义 | 英文写法与中文写法编出的目标码一致，这是底线 |

## 二、已修复的（曾经是坑）

| 曾经的症状 | 根因 | 修法 |

| `verify.ps1` 直接拒绝运行（`NOT BEEN SET UP YET`） | 别名缺失 | 修完后 **29 项全过** |

## 四、与上游的关系

- Chinese++ 是 **Clang/LLVM 的 fork**，不是包装脚本、不是预处理器 hack；
- 中文关键字改在**词法/语法层**，所以 clangd、`-ast-dump`、诊断位置等工具链全都正常；
- 许可：原创部分为**自定义条款**（源码公开 + 禁止重新发布），见仓库 `LICENSE-SCOPE.md`；
- **独立性声明**：本项目与 **Standard C++ Foundation / CppCon** 无隶属或背书关系，
  不使用 C++ 官方徽标的**修改版或衍生版**；主图标为自绘（红底「中」字）。

## 五、怎么复核我这套说法

```powershell

pwsh -File <包根>\verify.ps1

# 2) 中文头不靠 -I
chinese++ -std=c++20 你好.cpp -o 你好.exe; .\你好.exe

# 3) 真实搜索路径
chinese++ -x c++ -E -v -

# 4) 关键字不能当标识符
#    试着写 整数 大小() { 返回 1; }  →  必须报"（关键字） 大小 不能用作标识符"

# 5) 英文写法与中文写法等价
#    同一逻辑分别用 if/return 与 如果/返回 写，编译产物行为应一致
```
