# 第三批中文诊断 —— 待译清单 + 术语包（第二版，已并入外部复核意见）

> **这份文件的用途**：交给另一个 AI（或人）**挑错**，不是让它自由翻译。
> 请它回答"**我给的译法里，哪些与既有术语冲突、哪些读起来别扭、哪些地方我漏了**"。
>
> 项目：中文编程（Chinese++）—— Clang/LLVM 的 fork，报错正文用中文，
> 但 `error:` / `warning:` 前缀和 `[-Wxxx]` 选项名**保持英文**（CI 脚本和 VS Code 靠它抓日志）。
>
> **第二版改动**：并入 2026-09-23 外部复核意见。复核指出 4 条，经核实 **3 条为真、1 条为误读**；
> 另外它间接逼出了本项目一条**从未写下来的翻译规则**（见第二节规则 8）。逐条处理记录见第五节。

---

## 一、给审查者的任务

1. **不要重译一遍**，针对候选译法给意见。
2. 优先挑三类问题：**与既有术语冲突** > **读起来别扭** > **我漏掉的**。
3. **不要动占位符**：位置、序号、竖线数、分支数、**分支顺序**一律不能改（有机器校核器把关）。
4. **不要把这些改成英文**：`error:`/`warning:`/`note:` 前缀、`[-Wxxx]`、源码标识符、
   以及**"要你敲进去的那个词"**（见规则 8）。
5. **你无法验证**（跑不了我们的编译器），所以结论是**建议**；最终以
   `python tools\diag_id_lookup.py --check-table` 与 26 个渲染用例为准。
6. 输出格式：`ID → 结论（同意 / 建议改成 X / 理由）`，最后附"我担心的其它地方"。

## 二、硬约束（翻译时必须满足）

| # | 约束 |
|---|---|
| 1 | **只增不改**：不动任何 `Diagnostic*.td`，只往中文表里加条目 |
| 2 | **查不到就回退英文**，所以这表永远可以分批做、永远不完整 |
| 3 | **占位符一个都不能动**（位置/序号/竖线/分支数/**分支顺序**） |
| 4 | 允许的两种轻微改动：`%sN`（英文复数 s）**直接删掉**；`%ordinalN` 可写成 `%N` |
| 5 | **术语与关键字表逐字一致**：`类型`(class) `名域`(namespace) `结构`(struct) `常量`(const) `重写`(override) `重载`(overload) `显式`(explicit) `虚`(virtual) `类型别名`(typedef) `常量表达式`(constexpr) `静态断言`(static_assert) `静态转换`(static_cast) `重释转换`(reinterpret_cast) `运算符`(operator) `类型名`(typename) |
| 6 | **只换正文**：前缀、`[-Wxxx]`、行列号、源码片段、插入提示都不受影响 |
| 7 | **排版：词块边界留空格。** `缺少 非限定标识符`、`未使用的形参 'param'`。**不能写成 `缺少非限定标识符`**（汉字连在一起不利于阅读） |
| 8 | 🆕 **正文里那个词指什么，决定用中文还是英文**（既有 32 条背后其实一直遵守这个区分，但从没写下来）：<br>· 指**"你写的那个构造"** → **中文拼写**。先例：`unused typedef '丙'` 被改成 `未使用的 类型别名 '丙'`（.def 里明确写过"保留英文 typedef 是错的"）<br>· 指**"你要敲进去的那个词/符号"** → **保留英文**。先例：`missing 'typename' prior to …` 保留 `'typename'` |
| 9 | 🆕 **标点一律全角**（`；：。，`），代码/关键字/选项名里的符号除外。既有 32 条实测：全角 `；：` 47 处，中文正文里没有半角分号或冒号 |
| 10 | 🆕 **概念名现在就要定表**（见下文第三节末），否则同一概念迟早出现两套写法 |

### 明确**不做**的

| 次数 | 诊断 ID | 为什么不做（描述已按复核意见收紧） |
|---|---|---|
| **107** | `note_unsatisfied_trait_reason` | 实测 **42 个顶层分支、10 个 `%select`（其中 9 个嵌套）**；顶层那个 select 里有 **28 个分支的原子画像完全相同（空）**，另有 9 个同为 `(%1,)`、5 个同为 `(%1,%2)`。所以"翻转顺序查不出来"**只在同画像组内成立**，并非"所有分支"。这条翻错风险极高，等有专门对照手段再做 |

### 需要现在定下来的概念名（规则 10）

第 12 条与"不做"的那条是同一族（trait reasons）。**不做**那条将来要做时，这些词必须逐字一致，否则会出现"平凡可重定位 / 可平凡重定位"两套写法：

```
trivially relocatable → 可平凡重定位      trivially copyable → 可平凡复制
empty                 → 空                standard-layout    → 标准布局
aggregate             → 聚合              final              → 最终
abstract              → 抽象              polymorphic        → 多态
```

## 四、请审查者特别回答的问题

1. **规则 8 这个区分站得住吗？**（"指你写的构造"→中文拼写；"指你要敲的词"→保留英文）
   它是我从两条既有先例里反推出来的：`typedef`→中文、`'typename'`→英文。
2. 第 2 条的引号：写 `'静态断言'` 还是 `静态断言`？（先例 `未使用的 类型别名 '丙'` 没给关键字加引号）
3. 第 8 条 `编译期常量` 这个说法准确吗？会不会和 `常量表达式` 还是太近？
4. 第 12 条把 7 个标签改成名词短语（`空类型`/`最终类`/`抽象类`），准确吗？`final` 说成「最终类」还是「final 类」？
5. **我漏了什么？哪一条会被误解？**
