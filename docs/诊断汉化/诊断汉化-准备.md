## 二、条目的真实格式（决定中文表怎么写）

从 `DiagnosticParseKinds.inc` 抽出的真实两行：

```
DIAG(compat_c2y_decl_statement, CLASS_WARNING, (unsigned)diag::Severity::Ignored,
     "'%select{if|switch}0' declaration statements are incompatible with C standards before C2y",
     884, SFINAE_Suppress, false, false, true, false, 3, 94, 0)
```

两个要点：

1. **诊断 ID 是第 1 个参数，消息是第 4 个** ✓
2. **消息里含占位符** ✓ —— `%0` / `%1` / `%select{甲|乙}0`
   → 中文表**必须原样保留占位符**，只翻占位符之外的字 ✓✓
   **这是最容易翻错的地方**（漏掉 `%0`、或把 `%select{...}` 的竖线写坏，都会让诊断报错或串位）

> ⚠️ **修正：抄英文一定要抄 `.inc`，不要抄 `.td`。**
> `.td` 里的 `%sub{select_ovl_candidate_kind}0,1,2` 和
> `%enum_select<Kind>{...}0` 在生成时已被展开成普通的 `%select{...}`。
> 实测：7248 条 `.td` 定义 → 7374 条生成条目，其中 **146 条**的名字在
> `.td` 里根本搜不到（`compat_c*` 那批来自 `multiclass` 实例化），
> **128 条**的文字与 `.td` 不同。拿 `.td` 翻译会整段漏掉分支。

## 三、表的结构（草案）

新文件 `clang/include/clang/Basic/ChineseDiagnostics.def`：

```
// 中文诊断表：诊断 ID -> 中文句子。
//
// 查不到就回退英文 —— 所以可以【分批做，永远不完整】，这不会造成任何错误。
// 占位符 %0 %1 %select{...}N 必须原样保留。
// 术语一律查《术语表》，不要凭手感翻。

ZH_DIAG(err_expected_semi_declaration, "声明末尾缺少 ';'")
ZH_DIAG(err_unknown_typename,          "未知的类型名 %0")
ZH_DIAG(err_undeclared_var_use,        "使用了未声明的标识符 %0")
```

**为什么按 ID 而不是按英文原文查**：一条英文可能对应多个 ID；而英文会随上游改写（ID 稳定）。

## 四、接在哪一层

| 位置 | 评价 |
|---|---|
| `clang/lib/Basic/DiagnosticIDs.cpp` 取消息处 | **推荐** ✓ 最集中，只影响最终文本，不动诊断分类/等级/SFINAE 抑制 |
| `Diagnostic.cpp` 的 `FormatDiagnostic` | 不推荐 ✗ 那里已是分段文本，拿不到干净的 ID |

**三条硬约束**：

1. **只换正文** ✓ —— `error:` / `warning:` 前缀、`[-Wxxx]` 选项名、行列号、源码片段一律不动。
   否则 CI 和编辑器里按 `error:` 抓取的脚本会**全断** ✗。
2. **查不到 → 原样返回英文** ✓✓ —— 这是"部分翻译安全"的保证，也是不需要追平上游的原因。
3. 表是编译期的，规模 7374 条，用简单的有序表即可 ✓（不必上完美哈希）。

## 八、为什么这件事值得排第一

| 理由 | 说明 |
|---|---|
| **接触频率最高** | 99 个关键字是中文，但一写错就整个回到英文 —— 这是"汉字第一公民"目前最刺眼的缺口 |
| **风险最低** | 纯文本，不碰 ABI/API/语义；英文源码照样编译；"无锁定"性质不受影响 |
| **架构可复用** | 与关键字表同构：**数据一张表、代码只有挂钩、查不到就回退** |
| **小步可停** | 每翻一条都是净收益，随时可以停在任意批次，不存在"做一半更糟" |
