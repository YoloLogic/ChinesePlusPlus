## 一、两条铁律（任何改动都不许破坏）

1. **完全是汉语书写的 C++ 标准库** —— 中文是正式拼写，英文照旧可用（加名字，不改名字）。
2. **随便拿一个开源 C++ 项目，用我们的编译器编，必须照样编得过。**

微软原库（361 个文件）**一个字节都不许动**：闸门里有一条 SHA256 逐文件比对守着（铁律①守卫）。

## 四、踩过的坑（都付过代价，别再踩）

0. **阻塞/模态 API 不许进真跑用例**（§18.45 实测）：`消息框` 用**隐藏 owner** 时虽然
   **不显示**，但**也没法从外部关掉** —— `PostMessage(WM_CLOSE)`、`PostMessage(WM_COMMAND, IDOK)`、
   对 OK 按钮 `SendMessage(BM_CLICK)`、同步 `SendMessage(dlg, WM_COMMAND, IDOK)` **四种全试过都不返回**；
   而换成可见 owner 就**会弹窗**（违背"用例不弹窗"）。
   ⇒ 它只能是**边界 + 永假分支（编译期类型检查）**。
   **真要真跑一个阻塞 API，必须**：线程里调 → 主线程**轮询标志位到上限**（`join` 没有超时）→
   到上限就 `ExitProcess` 放弃。**判据：准备把"会等用户"的调用写进用例之前，先用探针量一遍能不能取消。**

1. **文档里的数字会漂，而且漂的方向是"让人相信一件已经过期的事"** —— 所以四本台账都由机器生成、
   由守卫核对；手写文档里的数字由 `check_zhdocs.ps1` 与台账对拍；文档里的 ```cpp 块（含 `主函数` 的）
   会被**真编译**。**写文档时不要手写进度数字。**
   **§18.47 起连"库存数字"也对拍**（产物数 / 守卫道数 / 自测项数 / 道号），真来源见第三节那条；
   这条坑的教训是"**只守了一类数字**就等于别的数字没人守"：实测 `26 道守卫`（真实 16）、
   `产物 116`（真实 119）、`17 项自测`（真实 21）同时漂着，而守卫全绿。
   **PowerShell 的变量名大小写不敏感**（同 `$f`/`$F`）：`$I`（库存对象）被循环里的 `$i = 0` 覆盖后，
   通过行打印成**空值** —— "看着绿其实没查"的典型，所以**打印出来的数字必须非空、且是自己算出来的那个**。
2. **批量字符串替换要防自嵌套**：把 `码页` 换成 `代码页`，会把已存在的「代码页」变成「代代码页」。
3. **生成器改了、产物没重生成 = 假绿**：全量验证验的是**产物**，生成器改了旧产物照样全绿。
   **同理：按正则扫生成器表的守卫，只认它见过的那种条目形态** —— 给条目多写一个字段、
   或者写一种三元/四元不一致的条目，扫描会**静默失配**，而漏扫的名字**不会变成"未覆盖"，
   它只是"不存在"**（实测：实例化台账曾长期看不见 C 轨的值宏与全局变量，共 13 个名字；
   又因为表里多一个 `kind=` 字段，整个 `<Windows系统>` 32 个名字整条缺席）。
   ⇒ **动过生成器的表之后，要看守卫打印的数字（产物数 / 名字数）有没有跟着变**；
   `check_zhinst.ps1` 现在有一道「产物集合守卫」专门喊这件事（**两个方向都查**：
   盘上有台账没有 ⇒ 漏扫；台账有盘上没有 ⇒ **产物悄悄没了**）。
   **这条坑已经复现第 5 次了（§18.42）**：那条通用名字正则要求"三元以上"条目，
   而 `'原文'` 条目是 `@('原文','<整行源码>')` **两元** ⇒ `<窗口>`/`<绘图>` 里
   **51 个公开包装函数**（`注册窗口类`/`画线`/`创建按钮`/`取系统度量`…）**从来没进过台账**。
   修法：给它一个**不给自动探针**的 Kind（`包装函数`）—— 它们只能靠**真实用例**覆盖，
   于是"某个包装一次都没被用例碰到"会**直接报成未覆盖**（这才是机器判据）；
   并且加了"`@('原文',` 出现几次就必须匹配到几次"的**静默少扫**警告。
   ⇒ **经验：每加一种条目形态，先问"扫它的正则/守卫认不认"**（`make_zhc` 的 `'原文'`、
   `结构复制`、中文表键、`inc` 数组…每一种都咬过一次）。
   **更要命的是"守卫空跑也报通过"**：§18.26 把产品挪进子文件夹时实测到**三道守卫**
   （`check_zhforward` / `check_zhdef` / `check_zhname`）还在用 `Get-ChildItem $dir -File`（扁平）
   ⇒ 扫到 **0 个产物**却打印"通过（0 条…）"，而平时是 364 / 175 / 664 条。
   已给它们补上「**0 个产物就红**」（§15.3）并改走 `Get-ZhIncludeDirs`。
   **判据：任何"扫产物"的守卫都必须能区分"没问题"和"没看见"。**
4. **中文关键字不能当标识符**（99 个）：`自身` 是关键字，写成变量名会报错；产品名当类型用要写 `标准::双字`。
5. **`'甲'` 这种汉字字符字面量编不过**（UTF-8 三字节塞不进 `char`）：见 `tests\12-diagnostics\81_*.cpp`。
6. **C 函数没有"别名"机制**：`使用 std::fopen;` 引入的是【英文名】。函数只能靠**转发模板**
   （`模板 <类型名... 参数> 声明类型(自动) 名(参数&&... 值)`）—— 它**本来就是变参模板**，
   `printf` 一家也能转；真正转不了的只有**宏**（`va_start` 一族用 `#定义`，用时**不加** `标准::`）。
7. **Win32 里很多"函数"是宏**（`CreateFile` / `WriteConsole` / `GetModuleHandle`…）：一律指向显式的
   `…W` 真函数；系统头的用户必须拿到 `NOMINMAX` 与 `WIN32_LEAN_AND_MEAN`（`<Windows系统>` 自己兜，
   `#ifndef` 包住）—— 不给它们的**实测**后果见 `方案 §3.4.2`。
8. **别名层里不要碰 `std`**：所有中文名都落在 `标准` 里，跨头撞名是**重定义**（不是重载），
   有守卫（`check_zhforward.ps1`）盯着，`tools\verify_zhstdlib.ps1` 的组合探针也会当场报出来。
9. **包内脚本的编码 = 真缺陷来源**（§18.48 实测）：包里的 `.ps1` 由 **PowerShell 5.1** 跑，
   而 PS 5.1 读**无 BOM** 文件按 **ANSI 代码页**解码 ⇒ 默认中文 Windows（GBK/936）下，
   直接写在脚本里的**汉字会变乱码**（实测 `标准库` → `鏍囧噯搴?`，4 个目录名 0/3 对得上真实文件夹
   ⇒ cfg 指向不存在的目录、`#包含 <向量>` 失效）。**本机 ACP=65001 所以看不出问题**。
   规矩：① **功能性汉字一律用码点拼**（`[char]0x6807,…`），源码保持 ASCII；
   ② 打包时非 ASCII 的包内脚本**补 UTF-8 BOM**（`make_package.ps1` 已自动做）；
   ③ 判据：`packaging\verify.ps1` 必须是**纯 ASCII**（它自己会跑在 5.1 上）。
10. **凡是"我们放在 `-isystem` 的目录"，绝不能有 clang 资源目录里同名的头**（§18.48 实测）：
    clang 的 `-internal-isystem`（它自己的 `lib\clang\<ver>\include` 与 VS）排在**后面**，
    我们的目录排在**前面** ⇒ 同名会 shadow 掉 clang 自己那份。踩过的两个：
    `immintrin.h`（与 clang 的 `ia32intrin.h` 声明冲突，整份 `<vector>` 编不过）、
    `yvals_core.h`（clang 那份是 **`#include_next` 垫片**，抢在前面就把它的 `include_next` 断了）。
    ⇒ `tools\vendor_msvc_stl.ps1` 里把"clang 资源目录有的名字"算成**交集并排除**，不靠人记。
11. **mingw-w64 的头在 clang/MSVC 模式下要打三处一行补丁**（§18.48 批2，三处都实测过）：
    ① `_mingw.h:45` 在"非 `__GNUC__`"分支里 `#define __attribute__(x) /* nothing */` ——
       clang 在 MSVC 模式下没有 `__GNUC__` ⇒ **中招**：clang 自己的 intrinsic 头
       `typedef long long __m64 __attribute__((__vector_size__(8)))` 被吃成 `typedef long long __m64;`，
       `mmintrin.h:83` 就报「到内建类型的函数式转换只能带一个实参」，**整份 `<vector>`/`<windows.h>` 编不过**；
    ② `_mingw_mac.h`：`__MINGW_GNUC_PREREQ` 对 clang 给 1（让 `__MINGW_ATTRIB_*` 走 GNU 属性分支）；
    ③ `_mingw.h` 属性块的 `#ifdef __GNUC__` 也接受 clang（否则 `__MINGW_ATTRIB_NORETURN` 是**尾置
       `__declspec(noreturn)`** ⇒ `stdlib.h:388 顶层声明符之后缺少 ';'`）。
    三处都写在 `tools\vendor_mingw.ps1` 里（带命中次数断言），`SOURCE.txt` 记录**补丁后**的 SHA256。
12. **"不能抄"的具体清单**（§18.48 批2，每一件都写在 `vendor\compiler-support\` 的文件头）：
    `vcruntime.h`（`_HAS_CXX*` 其实由它提供；`_MSVC_CONSTEXPR` **必须为空**、`_MSVC_WARNING_LEVEL`
    **必须不定义**）、`vcruntime_new.h`（定位 new 的 inline 形式）、`vcruntime_typeinfo.h`（MSVC ABI 的
    `type_info`）、`vcruntime_exception.h`、`vcruntime_string.h`、`vcruntime_new_debug.h`、`stdint.h`
    （**mingw 的会让 clang intrinsic 崩**）、`stdio.h`（`_Mbstatet`）、`stdlib.h`（`_invoke_watson` +
    `abs(long/long long)` 重载）、`math.h`（C++ 下撤掉 mingw 的 `isfinite` 等函数式宏）、`time.h`（`timespec_get`）。
    ⚠ **别按"外形"批量补 SAL 宏**：`_Count_`/`_File_`/`_do_` 这类名字外形像 SAL，其实是**真标识符**，
    一次清空 98 个直接搞坏 `<xmemory>`。**逐条按编译器报错补**。
13. **判据脚本必须先删旧产物再编译**（§18.48 批2 踩到"假成功"）：没删旧 `.obj`/旧日志时，
    编译失败也会看到"产物在、日志有" ⇒ 看起来像通过。本项目最忌讳这一类，写完脚本先自问一句
    "这个通过是不是上一次留下来的？"。
14. **链接层的地基在 `vendor\crt\`（§18.48 批3）**：`libcmt.lib`（我们的 `mainCRTStartup` +
   手搓 `operator new/delete` + `std::_Facet_Register`）+ 从**我们随包的 DLL** 生成的导入库 +
   mingw 的系统导入库。改它们要走 `tools\vendor_crt.ps1`（带 `SOURCE.txt` 逐文件 SHA256 与 `-Check`）。
   三条实测陷阱：① **`-L`/`-Wl,-libpath:` 都排不到 VS 的 libpath 前面** ⇒ 必须把库**逐个按绝对路径**交给
   链接器（靠搜索顺序是假成功，`/verbose` 才看得出来）；② GNU 驱动下 **`-libpath:` 会被当成 `-l ibpath:`**；
   ③ 数据符号必须走 `__imp_`（**微软自己的 `msvcprt.lib` 也只有 `__imp_?cout@…`**）⇒ 手搓 `vcruntime.h` 里
   必须定义 `_CRTIMP2_IMPORT`/`_CRTIMP2_PURE`；**但这会让"也包含 STL `<cstddef>`"的 TU 撞
   `max_align_t`**（clang 的 `<stddef.h>` 已把它放全局名域）⇒ `vendor\crt\*.cpp` **故意不包含任何 STL 头**。
   ④ `atexit` **不在**我们的导入库里 ⇒ 清理动作由我们自己的启动对象调用（**批4 改了**：见下面 17）。
15. **PowerShell 的逗号比 `+` 结合得更紧**（§18.48 批4，一天里栽了两次）：数组字面量里写
    `@('a', 'mode = ' + $v)` 得到的是**四个**元素（`'a'`、`'mode = '`、`'$v'` 的值各占一个），
    不是三个。`packaging\install.ps1` 就因此把 `bin\toolchain.txt` 写成了 `mode = ` ＋ 单独一行，
    所有读它的脚本**静默退回"未知模式"**；同一天我在自己的判据脚本里也因为
    `$srcFlags + @('-v', $exe + '.cpp')` 得到 `$exe` 和 `.cpp` 两个参数而白跑一轮。
    **规矩**：要和 `+` 混用时**一律加括号**。同族的还有：`'-Wl,/verbose'` **必须加引号**，
    否则 PowerShell 在解析阶段就报"参数列表中缺少参数"。
16. **`$script:` 变量会穿透 dot-source**（§18.48 批4）：`tools\zh_includes.ps1` 里写
    `$script:ZhRoot = ...`，被 `make_zhcfg.ps1` dot-source 后，`$script:` 作用域就是**调用者的**
    ⇒ 它**把调用者的 `$ZhRoot` 参数覆盖掉了**，`-ZhRoot <包根>` 被静默忽略（cfg 指向仓库而不是包）。
    发行包里因为"包根恰好等于 dot-source 根"而侥幸正确。**规矩**：被 dot-source 的公共脚本里
    的脚本级变量要起**不会撞车**的名字（现名 `$script:ZhIncludeRoot`）。
17. **链接层补件（§18.48 批4，都在 `vendor\crt\`，走 `tools\vendor_crt.ps1`）**：
    `security-cookie.cpp`（`__security_cookie` 一族 + 手写汇编 `__chkstk`）、
    `startup-extra.cpp`（`atexit` → UCRT 的 `_crt_atexit`；**UCRT 里没有 `atexit`**）、
    `typeinfo.cpp`（`??_7type_info@@6B@` 与 `__type_info_root_node`；**这个文件必须用 `-fno-rtti` 编**，
    否则 clang 先把那个名字占成空声明、真 vftable 被改名成 `.1`）、
    `asan-annotate.cpp`（两个 ASan 注解开关，顶掉不可再发行的 `stl_asan.lib`）。
    bundled 的 cfg 也从 `-nostdlib` 改成四个 `/nodefaultlib:`，并加了
    `/include:??_7type_info@@6B@`（静态库顺序）与 `/nodefaultlib:stl_asan`（唯一会去 VS 目录读库的依赖）。
    验证脚本：`build\_review_own\batch4_judge.ps1`（六项真链真跑，含"ASan 真能抓容器溢出"）。
