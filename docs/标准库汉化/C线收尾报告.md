# C 线收尾报告（Chinese++ 的 C 库汉化，§18.58–§18.67，2026-10-07/08）

> **一句话**：26 个中文 C 包装头，中文名 **146 → 362**；逻辑缺口 **230 → 14**，
> 而剩下这 14 个**全部是硬边界**（12 个函数式宏 + 2 个 `_Mbstatet` 别名）——
> 也就是说：**除硬边界外，C 线已全覆盖**。

## 一、账（逻辑口径 = 一个中文名覆盖整族 f/l 重载）

| | 起点（§18.58） | 终点（本报告） |
|---|---|---|
中文名合计 | 146（类型 8 / 函数 132 / 值宏 6） | **362**（类型 64 / 函数 292 / 值宏 6） |
参考全集（逻辑口径） | 364 | 364（已覆盖 350） |
参考全集（符号口径） | 476（含 f/l 变体） | 476 |
逻辑缺口 | 218（旧口径）→ **230**（修正口径） | **14**（全是硬边界） |

⚠ **口径**：缺口 = **逐头缺口之和**。§18.65 修正过一次 —— 旧算法 `Σ参考 − Σ我们` 会把 12 个
"我们有、参考集里没有"的名字（`FLT_MAX`/`INT_MAX`/`Eof`/`va_list`/`nullptr_t`/`jmp_buf` …）
当成销账，所以 §18.58–§18.64 期间发布的所有缺口数字都**少 12**：
218→230、159→171、115→127、86→98、70→82、54→66、53→65。（销账后逐批递减，终点 14。）

## 三、剩下这 14 个：**硬边界**（不是"没做"，是"做不了/不该做"）

| 类 | 个数 | 名字 | 为什么 |
|---|---|---|---|
数学**函数式宏** | 12 | `fpclassify` `isfinite` `isinf` `isnan` `isnormal` `isgreater` `isgreaterequal` `isless` `islessequal` `islessgreater` `isunordered` `signbit` | 它们是**宏**、不是函数：`std::` 里没有可转发的实体。要汉化就得**自己写实现**（`#define` 宏层），而那正是用户裁定**不做**的"纯 C 别名层"。 |
MSVC 内部标签 | 2 | `_Mbstatet`（同时出现在 `cwchar` 与 `cstdio` 两个头的参考集里） | 它是 `mbstate_t` **同一个类型**的 MSVC 内部拼写；我们已用 `多字节状态` 覆盖 `mbstate_t` 本身。 |
C11 已删 | 0 | （`gets`） | 这套 STL 里 `std::gets` 根本不存在 ⇒ 无源可转（§18.19 已登记）。 |
系统 API / 不做纯 C 的头 | 0 | `threads.h`/`stdatomic.h`/`stdbit.h`/`stdnoreturn.h`/`stdckdint.h` | 用户裁定"不做纯 C" ⇒ 这几个头保持英文，不在 C 线的覆盖目标里。 |

## 四、判据与守卫（这一线真正贵的东西）

* **第 29 道守卫**（§18.58）：`tools\make_c_ledger.ps1 -Check` —— 台账与源码必须一致（新鲜度），
  并且台账自带**恒等式自检**：`Σ参考 = Σ我们 + Σ缺口 − Σ(我们多出来的)`，不成立就抛错。
* **第 30 道守卫**（§18.61）：`tools\check_zhhijack.ps1` —— 「同名既有 C 轨无约束变参、又有别的产物的
  **带类型重载** ⇒ C 轨那行必须带 `约束 (`」。管的是"同名**不同签名**之间的优劣关系"，
  与 `check_zhforward` 查的"同名同签名 = 重定义"是两回事（它俩谁也替代不了谁）。
* **同一天修掉的三个"判据自己的错"**（都补了自测/自检，不靠人记）：
  1. §18.58 的 f/l 合并判据：把 `strtoll`/`atoll`/`wcstoull` 当成长双精度变体、把 `nanf`/`nanl` 当 `nan` 重载
     ⇒ 缺口少算 7；改成"整族（X/Xf/Xl）存在才算重载族"。
  2. §18.59 / §18.61 两条守卫的**橡皮图章自测**：扫描函数无声忽略传入的 `$dir` ⇒ 自测 fixture 从没被扫过
     （原版直接红：4/5、4/6），而闸门跑的是**不带** `-SelfTest` 的那条 ⇒ 长期没人发现。
  3. §18.65 台账合计口径（见上面第一节的 ⚠）。

## 六、证据（都是真跑出来的，不是"应该能"）

* `tools\make_zhc.ps1`：C 轨真实用例 **28 / 28 通过**（每批都跑；带用例的头从 12 个涨到 **19 个**）。
* `tools\check_zhinst.ps1`（全量）：名字 **1600+ 个**，自动探针 / 用例覆盖 / **未覆盖 0**。
* 每一批都先在 `build\_cprobe\` 或 `build\_patch_18xx\` 里用**英文名**写探针真编译真跑，再翻成中文 ——
  靠这个抓到了我自己的一堆错（`wcsncmp` 期望值写反、`wmemcmp` 第三参是宽字符个数、`strtok` 是 2 参、
  `wctype` 参数是窄串、`mbrtoc16` 第一参是 `char16_t*`、把关键字 `结构` 当变量名、`@(@(a,b))` 被 PowerShell 展平…）。
* 台账生成器自带恒等式自检；闸门 20 道守卫全绿、每次提交的成功行都含「铁律①：全部通过」。
