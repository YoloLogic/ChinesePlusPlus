# 代理族内部名全中文 —— 裁定：暂不实施（2026-11-17）

## 结论

`_Container_base0` / `_Container_base12` / `_Container_proxy` /
`_Fake_proxy_ptr_impl` / `_Fake_allocator` / `_Bind` / `_Leave_proxy_unbound`
这一族**内部件**的中文名，**暂不实施**。

当前状态：代理族**借用 std 的类型身份**——
`细节::_假分配器` 是 `std::_Fake_allocator` 的别名，
`_Container_proxy_ptr` 等别名通过包含关系解析到 std 的那一份；
组合（双端队列 + 无序映射）已经可用。

## 判据（为什么不做）

1. **用户不直接写这些名字**：它们只出现在容器实现内部；
2. **报错里出现也无可操作性**：看到 `_Fake_allocator` 还是 `_假分配器`，
   对定位用户代码问题没有差别；
3. **自托管成本高**：要把整条迭代器调试链
   （`_容器代理 ↔ _迭代器基类12 ↔ _容器基类12`）抄成我们自己的中文版，
   并消除全部「借来的接收者」，等于重做一套调试容器机制；
4. **风险大于收益**：改错会波及所有容器头，需要多轮全量重生成验证。

## 前置条件与清单（将来若要做）

见 `tools\make_zhstdlib2.ps1` 里 §17.27.71 的注释：
先抄 `_Container_base0` / `_Container_base12`，再统一代理族所有别名点，
最后保证 include 顺序无关。
