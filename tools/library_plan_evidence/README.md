# 中文标准库方案：实测证据

这里回答一个问题：**"每个库复制一份、加中文名"之后，能不能做到
"用户想引用哪个就用哪个"？**

答案：**别名层能，成员级中文不能。**

证据由 `run.py` 现场跑出来（一条命令，会自己断言结论）：

```powershell
python E:\Chinese++\tools\library_plan_evidence\run.py
```

## 实测结果（2026-09-24）

| # | 场景 | 结果 |
|---|---|---|
| 1 | 只引中文副本 | ✅ 通过 |
| 2 | 原库 + 中文副本（include guard **不同名**） | ❌ `error: 重定义（名字） 'V'` |
| 3 | 中文副本 + 原库（同上，换个顺序） | ❌ `error: 重定义（名字） 'V'` |
| 4 | 中文副本 + 原库（guard **同名**，先引中文） | ✅ 通过 |
| 5 | 原库 + 中文副本（guard **同名**，先引原库） | ❌ `没有名为（成员名） '压入' 的成员` |

## 怎么读这张表

* **第 2、3 行**：两份头**各自独立**是最自然的写法，但那样两个头同时引就是硬错误 ——
  所以"用户想引用哪个就用哪个"字面上走不通。
* **第 4、5 行**：让中文副本**复用原库的 include guard**，重定义就没了。
  但代价是 **先被引的那个赢，另一个整个被跳过**：
  第 5 行里 `压入` 凭空消失。
* **第 5 行是真正的问题**，因为真实项目里 `#include <vector>` 经常被**其它头间接**
  带进来 —— **顺序不在用户手里**。用户会莫名其妙地遇到"`压入` 不存在"。

## 结论（写进路线图第 4.0 节）

| 你要的中文 | 能否"每个文件各选各的" |
|---|---|
| 类型别名（`标准::向量<int>`） | ✅ 能（别名不碰原库定义） |
| 自由函数（`标准::排序(...)`） | ✅ 能 |
| **成员函数（`表.压入(x)`）** | ❌ **不能**（成员属于类，必须在 `std::vector` 自己的定义里加；一旦加就是整条编译命令全局的） |

**而且成员级中文根本不需要两份头**：超集式复制是"只加不改"，
中文副本里英文成员一个没动，所以 `v.push_back(1)` 和 `v.压入(1)`
在**同一份头**里同时可用。于是：

> "用户想引用哪个" 变成 **"这次编译用不用中文库"**（`-nostdinc++ -isystem <目录>`），
> 而不是"这个文件引哪个头"。

## 这组文件为什么在 `tools\` 而不在 `tests\`

它验证的是 **C++ 语言与头文件组织方式**的性质，不是我们编译器的行为。
它是一次**设计决定的取证**，所以不参与 `run_all.ps1` 的通过计数。
放在 `tools\` 是因为：**文档里的断言必须能复跑** ——
本项目栽过多次"文档说会查、而检查并不存在"。
