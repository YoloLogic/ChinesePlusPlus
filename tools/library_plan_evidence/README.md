# 中文标准库方案：实测证据

这里回答一个问题：**"每个库复制一份、加中文名"之后，能不能做到
"用户想引用哪个就用哪个"？**

答案：**别名层能，成员级中文不能。**

证据由 `run.py` 现场跑出来（一条命令，会自己断言结论）：

```powershell
python E:\Chinese++\tools\library_plan_evidence\run.py
```

## 实测结果（2026-09-24）

三层，一层比一层糟。

### A. 同一个文件里同时引

不需要任何库互相引用，用户自己就会撞上。

| # | 场景 | 结果 |
|---|---|---|
| A1 | 只引中文副本 | ✅ 通过 |
| A2 | 原库 + 中文副本（include guard **不同名**） | ❌ `重定义（名字） 'V'` |
| A3 | A2 换个顺序 | ❌ 同上 |
| A4 | 中文副本 + 原库（guard **同名**，先引中文） | ✅ 通过 |
| A5 | 原库 + 中文副本（guard **同名**，先引原库） | ❌ `没有名为（成员名） '压入' 的成员` |

### B. 库之间互相引用

`lib_uses_chinese.h` 模拟一个**第三方库的头**，它内部用了中文成员。

| # | 场景 | 结果 |
|---|---|---|
| B1 | 先引库，再引英文 `<vector>` | ✅ 通过 |
| B2 | **先引英文 `<vector>`，再引库** | ❌ 错误指向 `lib_uses_chinese.h:6` |

B2 的错误指向**用户没写过、也改不了的那个文件**。真实项目里 `<vector>`
常被别的头**间接**带进来 —— 顺序不在用户手里。

### C. 跨翻译单元：这一层**不报错**

`a.cpp` 引 `vec_orig.h`、`b.cpp` 引 `vec_zh.h`，各自用各自的成员：

| # | 场景 | 结果 |
|---|---|---|
| C1 | 三个 TU 各自编译 + 链接 + 运行 | ✅ 全部成功，`sizeof` 一致，**零诊断** |

## 怎么读这三层

* **A 层**：报错，但会连带否掉"两份头并行"这个最自然的写法。
* **B 层**：报错，但报在别人的头文件里，用户看不懂也改不了。**这是用户问的那一层。**
* **C 层**：**不报错**。
  两个 TU 里 `my::V<int>` 的定义不同，属 `[basic.def.odr]` 的 **IFNDR**
  （ill-formed, **no diagnostic required**）。
  这里碰巧能跑，只因为差异仅在**成员函数**、布局相同（`sizeof` 都是 8）。
  一旦中文副本动了数据成员或对齐，跨 TU 传对象就会内存错乱，**而依然没有任何提示**。

> **C 层是三层里唯一致命的一层**：A、B 至少会拦住你；C 层给你一个
> 编得过、链得过、跑得动、看不出任何异常的程序。

### D. 中文【头文件名】副本 —— 唯一零风险、现在就能做的一步

`向量` 这个文件（注意：**没有扩展名**，就是一个标准库风格的头）内容是
`#include <vector>` + `namespace 标准 { 别名 }`。

| # | 场景 | 结果 |
|---|---|---|
| D1 | `#包含 <向量>`，编译 + 运行 + 中文名对象传给收 `std::vector<int>&` 的函数 | ✅ 通过（`sizeof` 相同，能互传） |
| D2 | include 目录名也是中文（`-I 中文目录`） | ✅ 通过 |

**为什么它不受 A/B/C 三层影响**：它只是**多一个文件名**，内容是**别名**，
**没有改动 `std::vector` 的定义** —— 所以不存在"两份头并行"这件事。

这也是被推迟的库方案里**唯一现在就能做**的部分（路线图 4.4 节第 4 步）。
代价：给的是**类型名**，**不给中文成员**（`v.push_back(1)` 仍要写英文）。

## 结论（写进路线图第 4.0 节）

| 你要的中文 | 能否"每个文件各选各的" |
|---|---|
| 类型别名（`标准::向量<int>`） | ✅ 能（别名不碰原库定义） |
| 自由函数（`标准::排序(...)`） | ✅ 能 |
| **成员函数（`表.压入(x)`）** | ❌ **不能**（成员属于类，必须在 `std::vector` 自己的定义里加；一旦加就是整条编译命令全局的） |

**而且成员级中文根本不需要两份头**：超集式复制是"只加不改"，
中文副本里英文成员一个没动，所以 `v.push_back(1)` 和 `v.压入(1)`
在**同一份头**里同时可用。于是：

> "用户想引用哪个" 变成 **"这次编译用不用中文库"**（`-nostdinc++ -isystem <目录>`），
> 而不是"这个文件引哪个头"。

## 这组文件为什么在 `tools\` 而不在 `tests\`

它验证的是 **C++ 语言与头文件组织方式**的性质，不是我们编译器的行为。
它是一次**设计决定的取证**，所以不参与 `run_all.ps1` 的通过计数。
放在 `tools\` 是因为：**文档里的断言必须能复跑** ——
本项目栽过多次"文档说会查、而检查并不存在"。
